## О проекте

**Система электронной очереди для деканата** — это веб-сервис, разработанный для автоматизации процесса записи студентов на приём. Проект решает проблему живых очередей в деканатах университетов, распределяя нагрузку между сотрудниками и предоставляя студентам удобный инструмент онлайн-записи.

### **Целевая аудитория:**
- **Студенты** — для записи на приём без необходимости стоять в очереди
- **Сотрудники деканата** — для эффективного управления потоком посетителей
- **Администрация** — для контроля работы и аналитики

### **Ключевые цели:**
- Устранение живых очередей в коридорах деканата
- Равномерное распределение нагрузки между операторами
- Предварительная информация о цели визита
- Автоматизация планирования рабочего времени
- Уменьшение конфликтов по времени приёма

## **Что уже реализовано** 

### **1. Базовая архитектура**
- Flask приложение с модульной структурой
- PostgreSQL база данных с полной схемой
- JWT аутентификация и авторизация
- Ролевая модель (Студент/Оператор/Админ)

### **2. База данных (6 таблиц)**
- `users` — пользователи системы
- `services` — услуги деканата
- `tickets` — талоны (основная сущность)
- `windows` — окна/кабинеты приёма
- `schedule` — расписание работы
- `event_logs` — полное логирование событий

### **3. Полный набор API эндпоинтов**
- **Аутентификация**: регистрация, вход, профиль
- **Талонная система**: создание, статус, отмена
- **Операторские функции**: вызов, завершение, неявка
- **Админ-панель**: управление услугами, окнами, расписанием
- **Табло**: данные для отображения + статистика

### **4. Основная бизнес-логика**
- Генерация номеров талонов (формат A001, B002)
- Очередь FIFO с приоритетом по времени создания
- Автоматический расчёт ETA (ожидаемое время)
- 6 статусов талонов: NEW → WAITING → CALLED → SERVED/CANCELED/NO_SHOW
- Логирование всех событий для аудита

### **5. Готовые сценарии использования**
- **Сценарий 1**: Студент получает талон → оператор вызывает → табло обновляется → приём завершён
- **Сценарий 2**: Вызов талона → студент не явился → оператор отмечает NO_SHOW → вызов следующего
- **Сценарий 3**: Студент отменяет талон → очередь автоматически пересчитывается

### **6. Готовность к развёртыванию**
- Полный код на Python с комментариями
- SQL скрипты для создания БД
- `requirements.txt` со всеми зависимостями
- Инструкция по установке и запуску
- Примеры API запросов для тестирования

## **Быстрый старт**

### Установка за 5 минут:

```bash
# 1. Клонировать репозиторий
git clone https://github.com/yourusername/dean-queue-system.git
cd dean-queue-system

# 2. Настроить окружение
python -m venv venv
source venv/bin/activate  # venv\Scripts\activate на Windows
pip install -r requirements.txt

# 3. Поднять базу данных
createdb dean_queue
psql -d dean_queue -f schema.sql

# 4. Запустить сервер
python app.py
```

### Тестовые пользователи (после запуска schema.sql):
- **Админ**: `admin` / `password123`
- **Оператор**: `operator1` / `password123`
- **Студент**: `student1` / `password123`

## **API документация**

### Основные эндпоинты:

| Метод | Путь | Назначение | Роль |
|-------|------|------------|------|
| POST | `/api/login` | Вход в систему | Все |
| POST | `/api/tickets` | Создать талон | Студент |
| POST | `/api/operator/next` | Вызвать следующего | Оператор+ |
| GET | `/api/display/state` | Данные для табло | Публичный |

### Пример запроса:
```bash
# Создание талона
curl -X POST http://localhost:5000/api/tickets \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{"service_id": 1}'
```

## **Разработка**

### Технологический стек:
- **Backend**: Python 3.8+, Flask, SQLAlchemy
- **База данных**: PostgreSQL 12+
- **Аутентификация**: JWT (HS256)
- **Архитектура**: REST API, MVC-паттерн

### Правила разработки:
1. Все изменения через Pull Request
2. Тесты для новой функциональности
3. Комментарии к сложной логике
4. Соблюдение PEP8

```bash
# Установка dev-зависимостей
pip install -r requirements-dev.txt

# Запуск в режиме разработки
